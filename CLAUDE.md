# Warehouse OS — project brief for Claude Code

A warehouse system for a Montréal 3PL (Leedus Technologies builds it for the client). It replaces a WMS called "Express" plus Google Sheets. Three things the client cannot do today and this system must: see where every pallet is without going on site, know how much space is left for the next container, and tell the crew where each pallet goes. Details: `Project Overview.md` (the pitch and requirements as gathered), `README.md`, `docs/samples/README.md` (the client's real paperwork and what it changes), and the plan doc in Claude ("Warehouse System — Demo Plan & Architecture").

## Who and what

- **Client:** a 3PL with 4 warehouses; the pilot is one site, then the other 3 (`Project Overview.md`, Sept 18, has the goals in the client's words). Pilot site: 5020 rue Courval, Saint-Laurent (Pride Container Services on the paperwork; sketch titled "Happy's warehouse"). L-shaped, 47.5 × 45.7 m + 15.5 × 7.3 m annex ≈ 2,284 m². Three dock doors on the east wall (overview and sketch agree; the questionnaire said 4 + a bay), a scale, the office in the south-east corner. A second site is in Lachine (150 boul. Montréal-Toronto).
- **Rules the client set:** imperial units, English and French, roles for managers, office staff and drivers; only a manager can override a placement and every override needs a reason. Camera priorities in their order: confirm the spot, follow every pallet, show full/empty spots, measure pallets at the dock.
- **Operation:** ~20 customers, 20 containers a week (60 at peak), 5 staff at peak (2 forklifts, 1 office). 80% of pallets leave within a day (cross-dock); 5 customers are billed per carton and pick almost daily; the crew digs out a blocked pallet half the time. Customs bonded area planned.
- **Paperwork reality (see `docs/samples/`):** inbound documents list SKU + PO + case pack + units + cartons, never pallets, dims or weight; the warehouse builds the pallets and the current system gives each one a 10-digit lot number; outbound requests are by SKU + PO + cartons; the warehouse prints the packing slips and BOLs; some goods are bundles of 5.8 m billets, not pallets; weights come in kg and lb.

## Stack and conventions

- Next.js 16 App Router, TypeScript, Tailwind 4, Drizzle ORM on better-sqlite3 (`data/warehouse.db`, created and seeded on first run). Production target: same schema on Postgres.
- **All writes are server actions in `src/lib/actions.ts`** (`"use server"`), called from `<form action>`. Pages are server components; `src/components/WarehouseMap.tsx`, `Nav.tsx` and `PrintButton.tsx` are the only client components. No API routes, no client-side fetching.
- Reads live in `src/lib/queries.ts`; business rules are plain TypeScript with no framework imports: `slotting.ts` (which spot and why), `blocking.ts` (what is in the way), `capacity.ts`, `billing.ts`, `emailParser.ts`.
- Layout is generated, not stored by hand: `src/db/layout.ts` → `npm run db:reset`. Change the building or the racks there.
- Every pallet event is a row in `movements` (also the customs audit log) and a line in `events` (the activity feed). Keep that: write both when you add a new action.
- Money in cents, weights in lb in the schema today (kg arrives on the client's receipts: store the unit when you add kg), dimensions in inches, map coordinates in feet.
- Next 16 specifics: `params`/`searchParams` are Promises (`await props.params`); typed as `PageProps<"/route/[id]">` (generated by `next typegen`, run it before `tsc`); every page is `force-dynamic` via the root layout; Turbopack is the default; `middleware.ts` is now `proxy.ts`.
- Demo data is fictional (20 invented customers). The client's real documents are in `docs/samples/fixtures/*.json`. Do not commit `data/` or `.env.local`.

## Commands

```
npm run dev            # http://localhost:3000, seeds on first start
npm run db:reset       # wipe and reseed with "today" (restart dev after)
npm run db:check       # capacity, slotting examples, blocked pallets from the current DB
npm run typecheck      # next typegen + tsc
npm run lint
npm run build && npm start
```

Verify UI changes by loading the page in a headless browser (Playwright is fine) and checking for console errors; the demo path in `README.md` is the regression test.

## Backlog, in order

Derived from the client's documents. Each item names the fixture that proves it.

1. **Packing-slip lines and estimated pallets.** `shipment_lines` exists (schema) but nothing writes or shows it. Add lines to the shipment page and the shipment form (paste a table or add rows), estimate `expectedPallets` = ceil(cartons ÷ casesPerPallet) with casesPerPallet learned per SKU from past pallets, and print labels for the estimate plus spares. Fixture: `inbound-packing-slip-TCNU1215415.json` → receipt `warehouse-receipt-R03455-TCNU1215415.json` (44 pallets from 11 lines).
2. **Dock: build pallets from lines.** On the dock screen, receiving a pallet picks a shipment line (SKU/PO) and a carton count; the pallet inherits sku, poNumber, casePack, units; the line's `cartonsReceived` advances; the shipment closes when lines are complete. Lot number assigned at receiving, continuing the client's sequence (`lotNumber`, seeded from 0000548532).
3. **Outbound by SKU + PO + cartons.** Release form and email parser take lines like the Rossy pickup (`outbound-pickup-rossy-CMAU4573330.json`); an allocation step turns each line into pallets (whole pallets first, oldest lot first, at most one partial) and creates `outbound_lines` with `palletId`. Keep the pick-list and dig-out logic as is.
4. **Printable documents.** Packing slip and BOL as PDF from a release, with consignee, retailer PO / load number / appointment (`other-documents.json` → `outbound_packing_slip_ariella_walmart`, `outbound_crossdock_spectrum`), and the "to drivers" BOL with handling units and kg (`outbound_bol_kromet_billets`). 8. **Multi-site.** The app reads `sites.findFirst()` everywhere; add a site switcher and per-site layout (move `SITE.outline` into the `sites` row). Second site: Lachine, billets.
9. **Stocktake mode** for launch day: walk the floor, print a label per existing pallet (with its current lot number), confirm the spot by scan.
10. **Logins and roles** (manager, office, forklift, customer), manager-only placement override with a mandatory reason, then the customer portal behind a login instead of a token.
11. **Mailbox connection** (IMAP/Gmail) feeding `/inbox`; PDF packing-list reading (`documents_sku_lot_handling` migration has the fields).
12. **French UI.**
